# 보안 설계

| 경계 | 설계 |
| --- | --- |
| 채널 → Gateway | 인증된 사용자만 접수·조회. 작업별 소유권과 채널 맥락을 확인 |
| 승인 → 실행 | 작업·승인 주체·대화 맥락·계획 해시를 대조. 변경된 계획과 재사용 승인을 차단 |
| 실행기 → 프로젝트 | 프로젝트별 읽기·쓰기 범위를 적용. 문서와 모델 출력은 검토 대상 데이터로 처리 |
| 결과 → 전달 | 수신 권한과 목적지를 확인. 알림은 상태와 필요한 사용자 조치 중심으로 구성 |
| 내부 기록 → 공개 문서 | 합성 예시로 작성. 자격증명, 설정, 기록, 백업은 별도 보관 |

## 예산 및 복구 명령

예산·복구 명령은 허용 목록에 있는 사용자의 Telegram 개인 대화에서만 허용합니다. 기본 알림 목적지와 요청자 인증은 독립적으로 평가합니다. 그룹, 채널, Desktop, 미허용 사용자 요청은 거부하고, 허용 목록이 없거나 잘못 구성된 경우에도 차단합니다. 복구 명령에는 대상 작업과 승인 맥락을 추가로 확인합니다.

## 프로젝트 쓰기와 기록

- 실행기에는 역할에 필요한 파일 접근 권한만 부여합니다. 문서나 패치에 포함된 지시가 사용자 승인 범위와 도구 권한을 변경할 수 없도록 합니다.
- 변경 전 기준본을 확인하고, 공동 저장소에는 잠금과 기준본 재확인을 적용합니다. 검증 가능한 사본과 적용 이력으로 부분 실패를 복구합니다.
- 진단 기록에는 필요한 상태와 오류 분류만 남깁니다. 인증 정보, 채널 식별자, 원문 요청과 민감한 파일 내용의 출력 범위를 제한합니다.

공개 전에는 문서와 예시뿐 아니라 커밋에 포함될 파일 목록과 커밋 작성자 정보도 확인합니다. Git 제외 규칙은 미추적 파일의 실수 방지를 보조합니다. 이미 추적된 파일과 커밋 이력은 별도로 확인해야 합니다.
