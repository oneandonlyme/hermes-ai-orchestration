# 오케스트레이션

## 계획과 승인

1. 요청자의 권한, 대상 프로젝트, 실행 모드를 확인합니다. 기본 모드는 Fixed입니다. Swap은 요청자가 명시적으로 선택하고 기능이 활성화된 경우에만 허용합니다.
2. Hermes가 모드, 단계별 담당 실행기, 작업 범위, 예상 호출 예산과 한도를 계획에 기록합니다. 비활성 Swap 요청은 차단하고 실행 기록과 예산 예약을 만들지 않습니다.
3. 승인 대기 상태에서 계획과 SHA 해시를 제시합니다. 승인 요청은 해당 작업, 승인 권한이 있는 주체, 요청 맥락, 계획 해시에 결합합니다. 계획이 바뀌면 새 승인을 받습니다.
4. 실행 직전에 승인과 예산을 다시 확인합니다. 중복 승인이나 동시 요청에서도 실행권과 예산이 한 번만 확보되어야 합니다.

## 실행과 검증

| 단계 | Fixed | Swap | 산출물 |
| --- | --- | --- | --- |
| 분석 | Codex | Claude | 요구사항, 작업 범위, 검증 기준 |
| 작성·수정 | Claude | Codex | 초안 또는 변경안 |
| 독립 검증 | Codex | Claude | 요구사항 충족 여부, 확인한 증거, 미해결 사항 |

검증 실행기는 작성 실행기와 다르게 배정합니다. 검증에는 원요청과 승인 범위, 변경 내용, 검증 기준을 전달합니다. 검증에서 발견된 범위 초과나 결함은 결과에 기록하고 완료 처리를 보류합니다.

Codex의 코드 변경은 패치로 받아 대상 범위와 적용 기준본을 확인합니다. 승인 범위 내에서만 적용하고 패치와 적용 결과를 원장에 연결합니다. 부분 적용이 의심되면 후속 단계를 멈추고 작업 공간과 적용 기록을 대조한 뒤 복구 여부를 결정합니다.

## 중단과 복구

| 상황 | 처리 |
| --- | --- |
| 승인 대기 | 계획만 보관하고 모델 호출 및 프로젝트 변경을 보류 |
| 예산 부족 또는 사용량 제한 | 진행을 보류하고 사유와 마지막 확인 단계를 기록 |
| 실행기 중단 또는 결과 불명 | 호출과 패치 적용 여부를 대조하고 확인 가능한 지점에서 재개 |
| 검증 실패 | 결함을 기록하고 수정 계획이 승인 범위를 바꾸면 재승인 |
| 검증 통과 | 결과와 검증 의견을 저장하고 완료 상태를 기록 |

재개 전에는 작업 소유권, 승인 범위, 남은 예산과 완료 단계를 확인합니다. 결과가 불명확한 호출은 재호출 전에 사용량과 실행 여부를 확인합니다. 장애에 따른 자동 역할 교체는 비활성화합니다.
