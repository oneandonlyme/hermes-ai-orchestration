# 테스트 전략

실제 업무 자료 대신 합성 요청과 격리 작업 공간을 사용합니다. 단위·통합 테스트는 모의 실행기로 호출 횟수와 쓰기 여부를 확인합니다. 실제 모델을 쓰는 시험은 사전에 승인된 격리 작업으로 제한합니다.

| 단계 | 검증 항목 | 합격 기준 |
| --- | --- | --- |
| 단위 | 역할 배정과 기능 플래그 | Fixed 기본, Swap 명시 선택, 비활성 Swap 차단 |
| 단위 | 승인 해시와 예산 | 계획 변경·잘못된 맥락·중복 승인은 실행 불가. 동시 예약에도 한도 준수 |
| 통합 | 채널과 작업 조회 | 접수·처리·조회에서 동일 작업 식별자 사용. 타인 작업 조회 거부 |
| 통합 | 예산 및 복구 권한 | 허용된 Telegram 개인 대화에서 기대 응답 본문 확인. Desktop·그룹·미허용 요청과 잘못된 설정은 차단 |
| P1-C A | 안정화 회귀 | 비활성 Swap 요청의 작업·실행 기록과 예산 예약 미생성. 기존 작업과 예산 원장 무변경 |
| P1-C B | 비실행 계획 | 동일한 합성 요청에서 Fixed·Swap의 식별자와 역할 구분. 두 계획 모두 승인 대기이며 모델 호출과 프로젝트 쓰기 0건 |
| P1-C C | 실제 협업 | 승인된 계획만 실행. 역할별 호출·결과·예산 정산이 일치하며 독립 검증 결과와 패치 적용 기록이 확인됨 |
| 장애 주입 | 사용량 제한·중단·부분 적용 | 확인된 단계에서 재개하고 호출, 패치, 예산 정산의 중복 방지 |
| 후속 통합 | 알림 전송 및 재시도 | 권한 있는 목적지에 필요한 상태만 전송. 재시도에도 사용자에게 중복 전달 방지 |

## 증거와 판정

- 격리 테스트 전후의 상태와 예산을 비교합니다. 기존 승인 대기·복구 대기 작업의 승인 해시와 상태를 포함합니다.
- 비실행 시험에서는 호출 카운터와 프로젝트 변경 여부를 확인합니다. 정상 응답 판정에는 전송 여부와 함께 응답 본문을 확인합니다.
- 결과는 통과, 부분 확인, 차단으로 기록합니다. 계획 생성, 사용자 승인, 실제 실행, 결과 검증을 각각 확인합니다.
